# The S&F Report binder

The client document, cover to back page. A4 landscape, one slide per ring-binder
page, punched on the left. `sf_report.py`.

## Page order

Design leads, the site check follows it, then the commercial pages. That order
is deliberate: the client opens the binder onto their garden, not onto a list of
Council overlays.

| Page | Source |
|---|---|
| How to use this template | static, internal, deleted before printing |
| Cover | **data**: client name, address, date |
| A personal note from Lee, plus why choose Zones | **data**: first name, address |
| Contents | static |
| Design section | the drawing set via `--plans`, or placeholders |
| Selections | placeholder: numbered legend keyed to the plan |
| YOUR SITE divider | **data**: address, record count, how many flagged |
| Site pages ×4 | **data**, generated by `deck_export.build_site_slides` |
| Scope of work, exclusions, consents | placeholder, plus a consent draft from the findings |
| Your timeline | placeholder |
| Your budget range | placeholder; `budget=(low, high)` when zones-qs can price it |
| Your budget range, allowances and exclusions | static, with bracketed site-specific allowances. Added 11 Aug 2026 from the SF_34 deck sent to 66 Rhinevale Close |
| How we work, 5 stages | static |
| Ready to go | **data**: address |

Everything not marked **data** carries the same bracketed guidance the
hand-filled template used to, waiting for Lee.

## Merge fields

Four: `{{Name}}`, `{{First Name}}`, `{{Site Address}}`, `{{Date}}`.

- Name comes from `--client`. Left as its token if not given, so it is visibly
  still to do rather than quietly blank.
- Address comes from the lookup when it succeeds (Council's tidied version,
  title-cased from their shouting caps), and from what the user typed when it
  does not. **Always pass the address**, whatever happened to the lookup.
- Date defaults to today.

## The drawing set

`--plans` takes a PDF or a single image. Every page becomes one binder page in
the design section, in order, replacing the 2D plan and 3D render placeholders.

Selections is kept even when sheets are supplied. It is not an image slot but a
numbered legend keyed to markers on the plan, and a drawing set's own materials
and planting pages show character rather than listing what goes where. Dropping
it silently took a standard page out of the binder with nothing saying so, which
Lee noticed immediately.

Sheets are drawn at A3 landscape, the same shape as an A4 binder page, so they
land at 1:1 with nothing cropped and no reflowing. Each keeps its own title
block and picks up the deck's footer and live page number, and sits inside the
margins so the punch misses the drawing. Rasterised at 200 dpi, which holds
1:100 annotations legible at A4.

Intermediates (rasterised sheets, site maps) go to a working directory, never
beside the output. The output usually lands in the client's job folder on Drive,
where 20 MB of stray PNGs would sync and sit there looking like deliverables.

## Design language

Tokens live in `brand.py`, shared page furniture in `slides.py`. Both the site
pages and the rest of the binder draw from them, so they agree by construction
rather than by two implementations being kept in step by hand. That is the whole
reason those modules exist; the deck used to be a separate Node codebase with a
mirrored token file and a comment asking future-us to change both together.

- Green `01632F`, ink `232823`, body `40483F`, muted `7B857C`, rule `E4E8E3`,
  tint `F2F6F2`, tint green `E8F0EA`, card `F7FAF7`.
- Amber `F4EFE6` on `8A6D3B` is internal-only and never survives into a printed
  client page. It marks what Lee fills in or deletes first.
- Montserrat headings, Open Sans body.
- A4 landscape 297 × 210 mm, margins left 25, right 15, top 14, bottom 16.
  **The 25 mm left margin is the ring binder punch. Nothing may sit inside it.**
- Every content page: small letterspaced green eyebrow over a large ink subhead,
  on white. Hairline footer, brand line left, live slide-number field right.
- Tables: green rule under the header row, hairline between rows, no vertical
  rules, no banding, white throughout. Header text is green and uppercase, not
  white on a green fill.

**Slide numbers must stay live fields**, not baked text, because optional slides
get deleted per job. `slides.slide_number()` has the working implementation.

## Optional slides

3D render and Selections carry an amber OPTIONAL banner and get deleted when
that deliverable is not part of the job. The 2D site plan always stays. The
contents page lists sections without page numbers, so deleting optional slides
breaks nothing.

## Known rough edges

- On A3 sheet 3, if a job has more than eight on-property findings the surplus
  drops into the line headed "NEARBY, NOT ON YOUR PROPERTY", which mislabels
  them. Unconfirmed items are ordered ahead so they can never be the ones
  mislabelled, but the underlying issue is still there. Marine Parade with 9
  findings hits it.
- The contents page still lists "3D renders" and "Selections" as separate
  deletable lines even when a drawing set has been supplied.
- The binder is A4 only. `--page a3` affects the standalone PDF and site slides,
  not `--report`, because the binder is a ring-binder document by definition.
