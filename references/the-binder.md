# The S&F Report binder

The client document, cover to back page. A4 landscape, one slide per ring-binder
page, punched on the left. `sf_report.py`.

## Page order

Design leads, the site check follows it, then the commercial pages. That order
is deliberate: the client opens the binder onto their garden, not onto a list of
Council overlays.

| Page | Source |
|---|---|
| How to use this template | static, internal, deleted before printing |
| Cover | **data**: client name, address, date |
| A personal note from Lee, plus why choose Zones | **data**: first name, address |
| Contents | static |
| Design section | the drawing set via `--plans`, or placeholders |
| Selections | placeholder: numbered legend keyed to the plan |
| Site pages ×3 | **data**, generated by `deck_export.build_site_slides()` |
| Scope of work, exclusions, consents | placeholder, plus a consent draft from the findings |
| Your timeline | placeholder |
| Your budget range | placeholder; `budget=(low, high)` when zones-qs can price it |
| Your budget range, allowances and exclusions | static, with bracketed site-specific allowances |
| How we work, where you are and what happens next | static |
| What happens next, Stage 3 | static |

Everything not marked **data** carries the same bracketed guidance the
hand-filled template used to, waiting for Lee.

## The master template

One file, in Drive, and it is the single source of truth:

    _Zones\Resources\Templates\SF-Presentation-Template-Landscape-v1.pptx

It is a working document, not a stripped shell: every page of the current
design with `{{merge}}` tokens and `[bracketed]` prompts, on the layouts and
theme from the deck Lee last sent. He opens it to hand-build a report. The
generator opens the same file for its layouts and theme and drops the pages,
because a report builds its own. One file doing both jobs is the point, since
two could disagree.

It is produced by the generator rather than maintained by hand, which is the
only way the template and the tool stay the same document.

| Layout | Carries | Used by |
|---|---|---|
| `Zones Cover` | nothing, the cover paints its own | cover |
| `Zones Page No Logo` | footer rule, footer brand line, centred live slide number | personal note, contents, drawing pages, Stage 3 |
| `Zones Page` | the same, plus the Zones logo at 227.3/9.6 | selections, the site pages, and every commercial page |

Page chrome is therefore identical on every page by construction, because it is
literally the same shapes on the layout, not redrawn per slide.
`slides.footer()` is a no-op on A4 for that reason; it still draws for the A3
sheets, which have no Zones master to inherit from.

**Refresh the master from a deck Lee has actually sent**, never by hand:

```bash
python tools/build_master.py "<the sent deck>.pptx"
```

That strips the slides, re-stamps the package as a template, writes it over the
master in place and refreshes the local cache. Edited in place, never
duplicated and renamed: a second copy is how the automation ended up serving an
outdated template last time. There is a mirror at
`_Zones\Operations\Resources\Templates` that has to be kept in step by hand,
because it is a separate file rather than a shortcut.

`slides.py` reads the master on every build and calls `strip_slides()` on it,
so a change Lee makes to it reaches the next report with nobody remembering to
sync anything. `templates/zones-sf-a4.pptx` is a cache of the last successful
read, already stripped, used when Drive is not mounted, so being offline costs
currency rather than the build. Do not hand-edit the cache.

python-pptx clones body placeholders from a layout but deliberately skips date,
footer and slide-number ones, so `slides.blank()` copies the slide-number
placeholder across by hand. Without that the page numbers do not print at all.

`templates/zones-logo.jpg` and `templates/stage-01..05.png` are the cover and
five-stage-strip images. They stay bundled because the stage photos were
slide-level in SF_34 and so do not survive into a master.

The standalone `--pptx` export shares these pages exactly. At A4 it produces
the same overview, findings and map, same order, same layouts.

## The disclaimer

The short form only, at the foot of the overview page: `DISCLAIMER_INTRO`,
`DISCLAIMER_LIABILITY` and the LINZ/Council attribution. Those are the parts
that carry.

There is no Important notice page at A4 in either output. Lee's call, 14 Aug
2026: the report is not a contract, and the full terms are already in the
signed S&F contract, so a page restating them made the document look like
something it is not. Do not reinstate it without asking him.

Every client-facing output carries the same block, from
`render.CLOSING_NOTICE`: the binder, both `--pptx` exports, both `--pdf`
setups and the Word export. The full seven-point notice is kept in the code
and still prints to the terminal, which is internal.

## SF_34 is the reference

`66_Rhinevale_Close_SF_34.pptx` in that job's `00_Quoting` folder is the deck
Lee actually sent. The page set here matches it. Anything the generator
produces that then gets deleted, reordered or rebuilt by hand before sending is
a bug in `sf_report.py`, not a step in the workflow.

Five such edits were being repeated on every job until 13 Aug 2026: the YOUR
SITE divider and the Important notice page both deleted, the site map moved
after the findings, How we work retitled, and the closing page rebuilt as
Stage 3, Detailed Planning & Costing. Checking heading by heading finds the
retitles; only a full side-by-side finds the deletions and the reorder, so do
the full one whenever the sent deck moves ahead of this.

### Verifying against it

Compare properties, not pixels. For each page, walk the shapes in
(top, left) order and compare kind, position, size, fill, line colour and
weight, and per run the font, size, weight, colour and letter-spacing. Ignore
run text, which is job specific.

Hold position comparisons to about 0.25mm. Tighter than that and you are
comparing PowerPoint's EMU rounding: SF_34's pages sit at 24.9, 25.0 and 25.1mm
for what is one margin, because they were dragged rather than typed.

Two differences in SF_34 are typing artifacts and are deliberately not
reproduced: the scope page sets its first category heading in each column at
10pt and the rest at 9pt, and the Stage 3 page has an empty italic run at the
end of a bullet.

### What cannot be reproduced

Scope and Timeline are the two pages with no job-independent content at all,
so what ships is the frame and bracketed prompts. The Gantt in particular was
dragged by hand in SF_34 and its month marks are not evenly spaced; the
generated one is on a regular grid, so a bar's position can be read off the
gridlines.

## Merge fields

Four: `{{Name}}`, `{{First Name}}`, `{{Site Address}}`, `{{Date}}`.

- Name comes from `--client`. Left as its token if not given, so it is visibly
  still to do rather than quietly blank.
- Address comes from the lookup when it succeeds (Council's tidied version,
  title-cased from their shouting caps), and from what the user typed when it
  does not. **Always pass the address**, whatever happened to the lookup.
- Date defaults to today.

## The drawing set

`--plans` takes a PDF or a single image. Every page becomes one binder page in
the design section, in order, replacing the 2D plan and 3D render placeholders.

Selections is kept even when sheets are supplied. It is not an image slot but a
numbered legend keyed to markers on the plan, and a drawing set's own materials
and planting pages show character rather than listing what goes where. Dropping
it silently took a standard page out of the binder with nothing saying so, which
Lee noticed immediately.

Sheets are drawn at A3 landscape, the same shape as an A4 binder page, so they
land at 1:1 with nothing cropped and no reflowing. Each keeps its own title
block and picks up the deck's footer and live page number, and sits inside the
margins so the punch misses the drawing. Rasterised at 200 dpi, which holds
1:100 annotations legible at A4.

Intermediates (rasterised sheets, site maps) go to a working directory, never
beside the output. The output usually lands in the client's job folder on Drive,
where 20 MB of stray PNGs would sync and sit there looking like deliverables.

## Design language

Tokens live in `brand.py`, shared page furniture in `slides.py`. Both the site
pages and the rest of the binder draw from them, so they agree by construction
rather than by two implementations being kept in step by hand. That is the whole
reason those modules exist; the deck used to be a separate Node codebase with a
mirrored token file and a comment asking future-us to change both together.

- Green `01632F`, ink `232823`, body `40483F`, muted `7B857C`, rule `E4E8E3`,
  tint `F2F6F2`, tint green `E8F0EA`, card `F7FAF7`.
- Amber `F4EFE6` on `8A6D3B` is internal-only and never survives into a printed
  client page. It marks what Lee fills in or deletes first.
- Montserrat headings, Open Sans body.
- A4 landscape 297 × 210 mm, margins left 25, right 15, top 14, bottom 16.
  **The 25 mm left margin is the ring binder punch. Nothing may sit inside it.**
- Every content page: small letterspaced green eyebrow over a large ink subhead,
  on white. Hairline footer, brand line left, live slide-number field right.
- Tables: green rule under the header row, hairline between rows, no vertical
  rules, no banding, white throughout. Header text is green and uppercase, not
  white on a green fill.

**Slide numbers must stay live fields**, not baked text, because optional slides
get deleted per job. `slides.slide_number()` has the working implementation.

## Optional slides

3D render and Selections carry an amber OPTIONAL banner and get deleted when
that deliverable is not part of the job. The 2D site plan always stays. The
contents page lists sections without page numbers, so deleting optional slides
breaks nothing.

## Known rough edges

- On A3 sheet 3, if a job has more than eight on-property findings the surplus
  drops into the line headed "NEARBY, NOT ON YOUR PROPERTY", which mislabels
  them. Unconfirmed items are ordered ahead so they can never be the ones
  mislabelled, but the underlying issue is still there. Marine Parade with 9
  findings hits it.
- The contents page still lists "3D renders" and "Selections" as separate
  deletable lines even when a drawing set has been supplied.
- The binder is A4 only. `--page a3` affects the standalone PDF and site slides,
  not `--report`, because the binder is a ring-binder document by definition.
